# Tender Radar KZ Commercial — тестовый кабинет, протокол 27

Эта отдельная копия обращается только к новому Supabase `aypqwhhplogolzczubwi`.
Старые root index.html/feedback-admin.html, рабочий репозиторий, портал и бот не заменяются.

Файлы: index.html — кабинет; feedback-admin.html — обработка обратной связи.
SDK Supabase закреплён на версии 2.117.3. В коде только publishable key, без серверных секретов.

Изменения: отдельное хранилище сессии; строгая проверка оплаченного срока; защищённый вывод сообщений;
постраничная загрузка подборок; загрузка тендеров партиями; проверка результата сохранения статуса;
Telegram через отдельного тестового бота /start; роль администратора из app_metadata.

Проверено: JavaScript parse; 12 проверок обработчиков в Node VM с имитацией DOM/SDK.
Полноценный браузерный тест не завершён: Chromium не установился (ошибка ZIP загрузки).
Настоящие signup/login, почтовые подтверждения, лицензия и доставка Telegram не проверены.

Копия пока НЕ опубликована. Не открывать file:// как способ полной проверки: для Edge Functions
нужен разрешённый HTTP(S) origin; emailRedirectTo зависит от фактического адреса страницы.
До положительной приёмки следует выбрать/настроить отдельный тестовый HTTPS адрес,
в новом Supabase Auth добавить его в Redirect URLs и проверить Site URL/SMTP.
Для origins кроме https://mnsystems.github.io настроить TRKZ_ALLOWED_ORIGINS новых Edge Functions.
Не добавлять адрес тестового кабинета в старый Supabase.

Для Telegram нужен отдельный тестовый бот и параметры TRKZ_TEST_* из протокола26.
Не использовать токен и webhook рабочего @mn_tender_radar_bot.
Для обратной связи отдельному новому тестовому администратору сервером назначить
app_metadata.tender_radar_admin=true; hardcoded email не выдаёт права.

Подборки будут пустыми, пока не проверены и не запущены новые сборщики.
Расписания, реальная покупка, перенос клиентов и переключение рабочего портала не входят в этот этап.
